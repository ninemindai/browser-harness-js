Browser Harness (JS) Architecture

Agent runtime + daemon are always local. Only Chrome itself may be remote (cloud-hosted, driven over wss://).

Local Machine

  • • Everything inside the slate boundary runs on the user's laptop (or CI runner)
  • • Agent runtime + daemon communicate over /tmp/bu-{NAME}.sock — a unix socket, so same host only
  • • Multiple named harnesses (BU_NAME) can coexist; each gets its own socket + daemon + log
  • • profile-use CLI also runs locally, but uploads cookies to the cloud over HTTPS

Browser Use Cloud

  • • api.browser-use.com/v3 — provisions remote browsers, stores cloud profiles
  • • Remote browser is a Chromium instance reachable over wss:// CDP
  • • Authenticated with X-Browser-Use-API-Key from .env
  • • Daemon PATCH-stops the remote on SIGINT/SIGTERM so it doesn't burn concurrency quota

Crossing the boundary

  • • The only traffic leaving the laptop is HTTPS (to the API) and WSS (to a remote Chrome)
  • • Local Chrome never leaves the machine — CDP is ws://127.0.0.1
  • • Switching local ↔ cloud is one env var: BU_CDP_WS — the rest of the stack is identical
  • • start_remote_daemon() fetches cdpUrl/json/version to resolve the wss:// path, then spawns the daemon with that URL
